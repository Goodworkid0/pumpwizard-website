## Guarded cutover

The initial verified snapshot was staged using four disjoint transfer streams.
The background deployment then verifies all staged SQLite hashes and table counts,
stops the workstation collector, checks writer locks and creates another frozen
snapshot. It transfers the final differences, verifies server data and configuration
identity, sets the container's data ownership, and starts only the server collector.

The current cutover snapshot is:
`/home/c/Desktop/projekti/pump-agent-backups/snapshots/cutover-20260913T004823Z`.
It and the original workstation data remain retained. Nothing is pruned.

Readiness must pass before the public proxy changes. The proxy operation tests all
six pages, health/catalog, private-file/operator-route denial and the existing
insidedb.ai pages/health. Public browser tests then exercise mobile layout,
comparison, paginated history, copied prompt/config links and research downloads.
If browser checks fail, the proxy is restored to the landing page.

Before remote collector startup, a failure attempts to restart the local collector.
After remote startup, a failure deliberately leaves the local collector stopped
to avoid divergent histories. Inspect the server ledger and deployment phase;
do not blindly restart the older local database or merge WAL files.
